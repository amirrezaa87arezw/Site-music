# سایت رسمی سایکو (PSYCHO)

سایتی حرفه‌ای برای معرفی و انتشار موزیک، با:
- هیرو سه‌بعدی متحرک (Three.js) با رنگ‌بندی بنفش-قرمز مطابق هویت برند
- پلیر موزیک سراسری (نوار پایین صفحه، در همه صفحات فعال)
- پنل مدیریت کامل: آپلود موزیک، مدیریت ادمین‌ها (مدیر اصلی می‌تواند ادمین جدید بسازد)، و صفحه‌ی لاگ/دیباگ
- کاملاً فارسی و راست‌چین (RTL)، ریسپانسیو برای موبایل و دسکتاپ

## ۱. اجرای محلی (روی سیستم خودت)

```bash
# نصب پکیج‌ها
npm install

# فایل env بساز
cp .env.example .env
# سپس مقادیر SESSION_SECRET و SUPER_ADMIN_USERNAME/PASSWORD را داخل .env عوض کن

# ساخت دیتابیس
npx prisma db push

# ساخت اولین مدیر اصلی (بر اساس مقادیر داخل .env)
npm run db:seed

# اجرای سایت در حالت توسعه
npm run dev
```

سایت روی `http://localhost:3000` بالا می‌آید و پنل مدیریت روی `http://localhost:3000/admin/login`.

## ۲. ساختار پروژه (خلاصه)

```
src/app/                 صفحات سایت (Next.js App Router)
  page.js                صفحه اصلی
  admin/login             ورود ادمین
  admin/(dashboard)        پنل مدیریت (محافظت‌شده با ورود)
  api/                    مسیرهای بک‌اند (ورود، آهنگ‌ها، ادمین‌ها، لاگ‌ها، سرو فایل)
src/components/          کامپوننت‌های رابط کاربری
src/lib/                 ابزارهای مشترک (احراز هویت، لاگر، پردازش آپلود، دیتابیس)
prisma/schema.prisma     ساختار دیتابیس (Admin, Track, Log)
```

فایل‌های صوتی و کاور مستقیم داخل دیتابیس PostgreSQL ذخیره می‌شوند (نه روی دیسک)، چون دیسک اپلیکیشن روی Railway دائمی نیست ولی دیتابیس Postgres (به‌عنوان یک سرویس مدیریت‌شده) دائمی و پایدار است.

## ۳. آپلود روی Railway (میزبانی رایگان)

1. یک ریپازیتوری گیت‌هاب از این پروژه بساز و کد را در آن push کن.
2. در [railway.app](https://railway.app) وارد شو → **New Project** → **Deploy from GitHub repo** → ریپازیتوری را انتخاب کن.
3. یک دیتابیس Postgres اضافه کن: داخل همون پروژه، دکمه‌ی **"+ New"** یا **"Create"** → **"Database"** → **"Add PostgreSQL"**. Railway خودش یک سرویس دیتابیس دائمی می‌سازد.
4. برو داخل سرویس اصلی سایت (نه سرویس دیتابیس) → تب **Variables** → این متغیرها را اضافه کن:
   - `DATABASE_URL` = روی مقدار کلیک کن و بنویس `${{ Postgres.DATABASE_URL }}` (این یک رفرنس به دیتابیسی است که ساختی؛ Railway خودش مقدار واقعی را جایگزین می‌کند - اگر اسم سرویس دیتابیستو چیز دیگه‌ای گذاشتی، به‌جای `Postgres` همون اسم رو بذار)
   - `SESSION_SECRET` = یک رشته طولانی و تصادفی
   - `SUPER_ADMIN_USERNAME` = نام کاربری دلخواه برای مدیر اصلی
   - `SUPER_ADMIN_PASSWORD` = رمز عبور قوی
5. Railway به‌صورت خودکار از `package.json` دستور build (`npm run build`) و start (`npm start`) را اجرا می‌کند.
6. بعد از اولین دیپلوی موفق، از تب **Console** سرویس اصلی، این دو دستور را بزن:
   ```bash
   npm run db:push
   npm run db:seed
   ```
   این‌بار چون دیتابیس روی Postgres دائمی است، دیگر لازم نیست بعد از هر ری‌استارت این کار را تکرار کنی.
7. آدرس داده‌شده توسط Railway را باز کن، وارد `/admin/login` شو و با نام کاربری/رمزی که در مرحله ۴ گذاشتی وارد شو.

## ۴. بعد از ورود به پنل مدیریت

- **مدیریت موزیک‌ها**: عنوان، هنرمند، فایل صوتی و کاور را آپلود کن. می‌توانی یک آهنگ را به‌عنوان «آخرین انتشار» علامت بزنی تا در صفحه اصلی نمایش داده شود.
- **مدیریت ادمین‌ها** (فقط مدیر اصلی): می‌توانی ادمین‌های جدید با نقش «ادمین معمولی» یا «مدیر اصلی» اضافه یا حذف کنی.
- **لاگ‌ها**: هر ورود، آپلود، خطا و رویداد مهم دیگر اینجا با زمان دقیق ثبت می‌شود — برای دیباگ و بررسی مشکلات.

## ۵. بکاپ‌گیری و انتقال بین پروژه‌های Railway

اگه یه روزی خواستی همه‌چیز رو به یه پروژه/اکانت دیگه‌ی Railway منتقل کنی، از بخش «بکاپ» تو پنل مدیریت استفاده کن (`/admin/backup`):

- **دانلود بکاپ**: یک فایل zip شامل تمام آهنگ‌ها (با خود فایل صوتی/کاور) و اکانت‌های ادمین (رمزهای هش‌شده، نه متن ساده) می‌سازد و دانلود می‌کند.
- **بازیابی بکاپ**: همان فایل zip را روی پروژه‌ی جدید آپلود می‌کنی؛ آهنگ‌ها و ادمین‌ها بازسازی می‌شوند (چیزی حذف نمی‌شود، فقط merge/آپدیت).

چون حالا دیتابیس روی Postgres دائمی است، دیگه لازم نیست به‌خاطر ری‌استارت یا دیپلوی جدید بکاپ بگیری — فقط برای وقتی که می‌خوای به یه پروژه‌ی کاملاً جدید (مثلاً اکانت دیگه) منتقل بشی لازمت می‌شه.

## ۶. دسترسی کاربران ایرانی به سایت (هاست آمریکایی)

سرورهای Railway در آمریکا هستند و ممکن است بعضی کاربران داخل ایران بدون فیلترشکن به سایت دسترسی نداشته باشند. این مشکل شبکه/زیرساخت است، نه چیزی که با تغییر کد حل شود — دو راه رایج:

- **راه ساده (پیشنهادی)**: یک دامنه بخر و آن را از طریق **Cloudflare** (رایگان) به‌عنوان proxy جلوی آدرس Railway بگذار. IPهای Cloudflare معمولاً در ایران بدون فیلترشکن در دسترس‌اند، حتی وقتی IP اصلی سرور فیلتر باشد. کافی است دامنه را در Cloudflare ثبت کنی، رکورد DNS را با حالت «Proxied» (ابر نارنجی) به آدرس Railway اشاره بدهی.
- **راه دوم**: با توجه به اینکه قبلاً یک تونل WireGuard/rathole بین ایران و آلمان راه انداخته بودی، می‌شه از همون منطق برای ریورس‌پروکسی کردن ترافیک سایت هم استفاده کرد — ولی برای یک سایت عمومی معمولاً Cloudflare ساده‌تر و پایدارتر است.

این موضوع به کدهای خود سایت ربطی ندارد و نیازی به تغییر در پروژه‌ی Next.js نیست؛ فقط یک تنظیم DNS/شبکه است.

## نکات امنیتی

- حتماً `SESSION_SECRET` و رمز مدیر اصلی را طولانی و غیرقابل حدس انتخاب کن.
- بعد از اولین ورود، پیشنهاد می‌شود یک ادمین جدید با رمز دلخواه خودت بسازی و ادمین seed-شده را حذف کنی (یا رمزش را از طریق دیتابیس عوض کنی).
- حجم فایل صوتی حداکثر ۴۰ مگابایت و کاور حداکثر ۸ مگابایت است (قابل تغییر در `src/lib/upload.js`).
